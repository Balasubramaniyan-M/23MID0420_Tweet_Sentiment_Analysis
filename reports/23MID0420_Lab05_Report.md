## 2. Problem Framing

### Task Definition
- **Prediction unit:** One tweet
- **Input:** Tweet text (with airline entity context)
- **Target:** Dataset-defined sentiment (negative / neutral / positive)
- **Task type:** Supervised multiclass text classification

### Business Context
The system could support product feedback analysis, service-quality monitoring, issue discovery, and campaign monitoring. However, predictions are analytical signals, not objective measures of customer satisfaction. Social-media samples are non-representative of the complete customer population.

## 3. Dataset Provenance and Governance

### Source
The Twitter US Airline Sentiment dataset was sourced from Kaggle (CrowdFlower), containing approximately 14,640 tweets collected in February 2015 about six US airlines. Labels were crowdsourced via CrowdFlower human annotators.

### Class Distribution
The dataset is significantly class-imbalanced:
- **Negative:** ~63% (majority class)
- **Neutral:** ~21%
- **Positive:** ~16%

This imbalance justifies using macro F1 as the primary evaluation metric.

### Leakage Prevention
Five leakage-risk columns were identified and excluded:
- `airline_sentiment_confidence` — reveals annotation certainty
- `negativereason` — post-labeling metadata
- `negativereason_confidence` — post-labeling confidence
- `airline_sentiment_gold` — alternate label source
- `negativereason_gold` — alternate reason source

Six privacy-sensitive columns (username, coordinates, location, etc.) were also excluded.

### Data Quality
- Text and target columns have no missing values
- Duplicate tweet text instances are documented but retained
- The dataset card is available at `data/README.md`

## 5. Tweet Preprocessing

### Strategy: Minimal Normalization
We apply minimal preprocessing that preserves sentiment-bearing features:

| Operation | Purpose |
|---|---|
| URLs → `<URL>` | Normalize noise |

## 13. Error Analysis

10 actual misclassified test tweets were inspected (see `outputs/results/error_analysis.csv`). Common error patterns include:

1. **Negation confusion:** Tweets with negation patterns that reverse sentiment
2. **Sarcasm/irony:** Positive-sounding words with negative intent
3. **Mixed sentiment:** Tweets containing both praise and complaint
4. **Short/ambiguous tweets:** Insufficient context for reliable classification
5. **Domain-specific terms:** Airline jargon not fully captured by TF-IDF

## 14. Responsible Analytics

### Privacy
- Usernames, coordinates, and locations are excluded from modeling
- All tweet examples are anonymized in reporting
- No individual user profiling is performed

### Sampling Bias
- Dataset represents only February 2015 US airline tweets
- Twitter users are not representative of all customers
- The ~63% negative prevalence reflects Twitter complaint behavior, not actual service quality

### Annotation Bias
- Crowdsourced labels contain inherent inter-annotator disagreement
- Neutral vs. mildly negative/positive boundaries are subjective

### Misuse Boundaries
- Predictions are analytical signals requiring human oversight
- Not suitable for automated customer punishment, discrimination, or autonomous decisions

## 15. Limitations

1. Sampling bias (February 2015, US airlines only)
2. Annotation noise (crowdsourced labels)
3. Sarcasm/irony not explicitly handled
4. Domain-specific — may not generalize beyond airlines
5. TF-IDF bag-of-words limitations (no word order, context)
6. Temporal shift (2015 language vs. current usage)
7. Class imbalance effects despite balanced weights
8. No conversation/thread context
9. Model probabilities not well-calibrated

## 16. Recommendation

For production deployment of tweet sentiment monitoring:
1. Use the selected model as a screening tool with human review
2. Retrain periodically to address temporal language shift
3. Consider Transformer-based models for improved sarcasm/context handling
4. Implement confidence thresholds to flag uncertain predictions for human review
5. Never use predictions for autonomous punitive decisions
